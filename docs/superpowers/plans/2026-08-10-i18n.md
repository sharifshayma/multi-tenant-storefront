# Arabic/English Internationalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let each store switch its entire UI (admin dashboard + storefront) between Arabic and English via one setting, translating all app chrome and flipping RTL↔LTR, while leaving user-entered content untouched.

**Architecture:** A dependency-free dictionary (`ar`/`en` objects of identical shape) plus a `t()` lookup helper. A new `Store.uiLocale` column drives which dictionary is used, `dir`/`lang`, and `Intl` formatting. Server components resolve the dictionary from store context; client components get it via a `LocaleProvider`. Phase A builds the engine + language setting + direction wiring; Phase B converts the ~85 string-bearing files area-by-area following a fixed recipe.

**Tech Stack:** Next.js (App Router, RSC), Prisma (PostgreSQL), Tailwind v4 (logical properties), Vitest.

## Global Constraints

- `Store.uiLocale` is `"ar" | "en"`, DB default `"ar"` — existing stores stay Arabic, no backfill.
- No i18n library; the dictionary + `t()` live in `src/i18n/`.
- `en.ts` is typed `typeof ar`, so a missing/renamed key fails `tsc` — this is the parity guarantee. `ar.ts` is the source-of-truth key set and is NOT declared `as const` (leaf types must widen to `string`).
- `t(dict, path, vars?)` returns the `path` string on a missing key (never throws).
- User-entered content (store name, product/collection titles & descriptions, hero/footer copy) is NEVER routed through `t()`.
- Server actions translate their own error messages via `store.uiLocale`; call sites keep showing `result.error` unchanged.
- Physical Tailwind direction classes are replaced with logical ones during conversion: `pr-*`→`pe-*`, `pl-*`→`ps-*`, `mr-*`→`me-*`, `ml-*`→`ms-*`, `text-right`→`text-end`, `text-left`→`text-start`, `right-*`→`end-*`, `left-*`→`start-*`, `rounded-l-*`→`rounded-s-*`, `rounded-r-*`→`rounded-e-*`. Neutral utilities (`text-center`, `gap-*`, `justify-*`) are left alone.
- UI copy in `en` matches the tone of the Arabic (concise store-owner-facing English); Arabic values are copied verbatim from the existing code (never re-authored).
- Test runner: Vitest (`npx vitest run <path>`). Typecheck: `npx tsc --noEmit`.
- The worktree has NO database; the migration is hand-authored (see Task 1) — never run `prisma migrate dev`.

## Conversion Recipe (shared by every Phase B task)

Each Phase B task converts a set of files. For EACH file:

1. **Identify app-chrome strings** — visible UI text, `aria-label`s, `placeholder`s, `title`s, and validation/toast messages that are hardcoded Arabic. Do NOT touch strings that render user data (e.g. `book.title`, `store.name`, `{store.heroSubtitle}`).
2. **Add keys** to BOTH `src/i18n/dictionaries/ar.ts` and `en.ts` under the task's namespace, mirroring structure. The Arabic value is the exact string currently in the code; the English value is a faithful translation. Reuse `common.*` for shared words (save/cancel/back/delete/loading/add/edit) instead of duplicating.
3. **For strings with dynamic parts** (counts, the item-noun, a name), use a `{placeholder}`: e.g. Arabic `"{n} نسخة إجمالاً"` / English `"{n} copies total"`, called `t(d, "admin.orders.totalCopies", { n: totalCopies })`.
4. **Replace** the hardcoded string with a `t()` call:
   - **Server component** (async, no `"use client"`): near the top, after resolving the store, add `const d = getDictionary(store.uiLocale as Locale);` and use `t(d, "…")`. If the component doesn't already have the store, resolve it the same way sibling code does (`getCurrentStore()` for admin, `resolveStorefrontContext` for storefront) — the store is already loaded in every page here.
   - **Client component** (`"use client"`): add `const { t, d } = useT();` from `@/i18n/LocaleProvider` and use `t("…")` (the hook's `t` is already bound to the active dictionary — see Task 3 signature).
5. **Swap physical→logical classes** per the Global Constraints list, in that file only.
6. Leave imports tidy (add `getDictionary`, `t`, `type Locale` from `@/i18n` for server files; `useT` for client files).

**Worked example — a server component (before → after):**

```tsx
// BEFORE (src/app/[storeSlug]/order/confirmation/page.tsx excerpt)
<h1 className="text-2xl font-extrabold">تم استلام طلبك!</h1>
<p className="mt-2 text-muted">سنتواصل معك قريباً.</p>
```
```tsx
// AFTER
import { getDictionary, t, type Locale } from "@/i18n";
// …inside the component, store already resolved as ctx.store…
const d = getDictionary(ctx.store.uiLocale as Locale);
// …
<h1 className="text-2xl font-extrabold">{t(d, "store.confirmation.title")}</h1>
<p className="mt-2 text-muted">{t(d, "store.confirmation.subtitle")}</p>
```
```ts
// ar.ts adds:  store: { confirmation: { title: "تم استلام طلبك!", subtitle: "سنتواصل معك قريباً." } }
// en.ts adds:  store: { confirmation: { title: "Your order was received!", subtitle: "We'll contact you soon." } }
```

**Worked example — a client component (before → after):**

```tsx
// BEFORE
"use client";

```
```tsx
// AFTER
"use client";
import { useT } from "@/i18n/LocaleProvider";

  const { t } = useT();
  return <button>{t("admin.orders.delete")}</button>;

```

```ts
import { ar } from "./dictionaries/ar";
import { en } from "./dictionaries/en";

export type Locale = "ar" | "en";
export type Dictionary = typeof ar;

export function getDictionary(locale: Locale): Dictionary {
  return locale === "en" ? en : ar;
}

export function dirFor(locale: Locale): "rtl" | "ltr" {
  return locale === "en" ? "ltr" : "rtl";
}

export function t(
  dict: Dictionary,
  path: string,
  vars?: Record<string, string | number>,
): string {
  const raw = path
    .split(".")
    .reduce<unknown>(
      (o, k) => (o && typeof o === "object" ? (o as Record<string, unknown>)[k] : undefined),
      dict,
    );
  if (typeof raw !== "string") return path;
  if (!vars) return raw;
  return raw.replace(/\{(\w+)\}/g, (_, k) => (k in vars ? String(vars[k]) : `{${k}}`));
}
```

### Task 3: `LocaleProvider` + `useT()` for client components

**Files:**
- Create: `src/i18n/LocaleProvider.tsx`

**Interfaces:**
- Consumes: `Locale`, `Dictionary`, `getDictionary`, `t`, `dirFor` from `@/i18n`.
- Produces:
  - `<LocaleProvider locale={Locale}>…</LocaleProvider>` (client component)
  - `useT(): { t: (path: string, vars?: Record<string, string | number>) => string; d: Dictionary; locale: Locale; dir: "rtl" | "ltr" }`

- [ ] **Step 1: Create the provider + hook.**

```tsx
"use client";

import { createContext, useContext, useMemo, type ReactNode } from "react";
import { getDictionary, t as translate, dirFor, type Dictionary, type Locale } from "@/i18n";

type LocaleContextValue = {
  t: (path: string, vars?: Record<string, string | number>) => string;
  d: Dictionary;
  locale: Locale;
  dir: "rtl" | "ltr";
};

const LocaleContext = createContext<LocaleContextValue | null>(null);

export function LocaleProvider({ locale, children }: { locale: Locale; children: ReactNode }) {
  const value = useMemo<LocaleContextValue>(() => {
    const d = getDictionary(locale);
    return { d, locale, dir: dirFor(locale), t: (path, vars) => translate(d, path, vars) };
  }, [locale]);
  return <LocaleContext.Provider value={value}>{children}</LocaleContext.Provider>;
}

export function useT(): LocaleContextValue {
  const ctx = useContext(LocaleContext);
  if (!ctx) throw new Error("useT must be used within <LocaleProvider>");
  return ctx;
}
```

- [ ] **Step 3: Implement the action.** Append to `src/actions/store.ts`:

```ts
export async function updateStoreUiLocale(
  locale: string,
): Promise<{ ok: true } | { ok: false; error: string }> {
  const store = await requireStore();
  if (locale !== "ar" && locale !== "en") {
    return { ok: false, error: "لغة غير مدعومة" };
  }
  await prisma.store.update({ where: { id: store.id }, data: { uiLocale: locale } });
  revalidatePath("/admin", "layout");
  revalidatePath("/", "layout");
  return { ok: true };
}
```

```tsx
"use client";

import { useState, useTransition } from "react";
import { useRouter } from "next/navigation";
import { updateStoreUiLocale } from "@/actions/store";

const LANGUAGES = [
  { code: "ar", label: "العربية" },
  { code: "en", label: "English" },
];

export function LanguageCard({ uiLocale }: { uiLocale: string }) {
  const router = useRouter();
  const [value, setValue] = useState(uiLocale);
  const [msg, setMsg] = useState<string | null>(null);
  const [pending, startTransition] = useTransition();

  function save() {
    setMsg(null);
    startTransition(async () => {
      const r = await updateStoreUiLocale(value);
      if (r.ok) {
        setMsg("تم تحديث اللغة");
        router.refresh();
      } else {
        setMsg(r.error);
      }
    });
  }

  return (
    <div className="flex flex-col gap-3 rounded-2xl border border-border bg-white p-5">
      <div>
        <h2 className="font-extrabold">اللغة</h2>
        <p className="mt-1 text-sm text-muted">لغة لوحة التحكم والمتجر معاً.</p>
      </div>
      <div className="flex flex-wrap items-center gap-2">
        <select
          value={value}
          onChange={(e) => setValue(e.target.value)}
          className="min-w-0 flex-1 rounded-lg border border-border bg-white px-3 py-2 text-sm font-bold text-ink outline-none focus:border-brand"
        >
          {LANGUAGES.map((l) => (
            <option key={l.code} value={l.code}>{l.label}</option>
          ))}
        </select>
        <button
          type="button"
          disabled={pending || value === uiLocale}
          onClick={save}
          className="rounded-lg bg-brand px-4 py-2 text-sm font-bold text-white disabled:opacity-50"
        >
          {pending ? "..." : "حفظ"}
        </button>
      </div>
      {msg && <p className="text-sm font-bold text-accent">{msg}</p>}
    </div>
  );
}
```
