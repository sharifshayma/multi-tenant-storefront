# Accounts (Plan 1 of 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single shared `ADMIN_PASSWORD` with real per-person accounts (email + password, sessions in Postgres) so the app is ready to have many owners, while the existing bookstore admin keeps working.

**Architecture:** Introduce [Better Auth](https://better-auth.com) as a self-hosted auth layer backed by the existing Prisma + Vercel Postgres. Better Auth owns the `User`/`Session`/`Account`/`Verification` tables, exposes its endpoints through one catch-all route handler, and provides a server-side `getSession` helper we call inside `src/proxy.ts` to guard `/admin`. The existing hand-rolled `jose` session and `ADMIN_PASSWORD` check are removed once the new flow works. No tenant/`storeId` concepts yet — that is Plan 2.

**Tech Stack:** Next.js 16 (App Router, `proxy.ts` middleware), Prisma 6 + PostgreSQL, Better Auth (email/password + `nextCookies` plugin), Vitest + happy-dom for tests, Zod for input validation.

## Global Constraints

- **Next.js version is 16.2.10.** APIs differ from older Next. Middleware lives in `src/proxy.ts` (Next 16 rename), not `middleware.ts`. Before writing any Next-specific code, confirm the exact API against the installed package per `AGENTS.md`.
- **Database:** PostgreSQL via Prisma. Connection env vars are `POSTGRES_PRISMA_URL` (pooled) and `POSTGRES_URL_NON_POOLING` (direct), already set. Do not rename them.
- **No per-user (per-MAU) auth fees** — auth stays self-hosted (Better Auth). No Clerk/Auth0.
- **The app must build and the bookstore must stay usable after every task.** Every commit compiles (`npm run build` clean) and the admin remains reachable. Never leave `/admin` unguarded between commits.
- **UI copy stays Arabic (RTL)** to match the current app; translation is a later sub-project. New user-facing strings are written in Arabic, mirroring existing components.
- **No `storeId`, `Store`, or multi-tenancy in this plan.** Accounts only.
- **Secrets:** add `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` to `.env`. Remove `ADMIN_PASSWORD` and `SESSION_SECRET` only in the final cleanup task, after the new flow is verified.

- [ ] **Step 3: Implement the guard**

Create `src/lib/auth-guard.ts`:
```ts
import { headers } from "next/headers";
import { auth } from "@/lib/auth-server";

export type CurrentUser = { id: string; email: string; name: string };

export async function getCurrentUser(): Promise<CurrentUser | null> {
  const session = await auth.api.getSession({ headers: await headers() });
  if (!session?.user) return null;
  const { id, email, name } = session.user;
  return { id, email, name };
}

export async function requireUser(): Promise<CurrentUser> {
  const user = await getCurrentUser();
  if (!user) throw new Error("Unauthorized");
  return user;
}
```

import { auth } from "@/lib/auth-server";

export function parseArgs(argv: string[]): { email: string; password: string; name: string } {
  const [email, password, name] = argv;
  if (!email || !password) {
    throw new Error('Usage: npm run create-user -- <email> <password> "<name>"');
  }
  return { email, password, name: name ?? email };
}

async function main() {
  const { email, password, name } = parseArgs(process.argv.slice(2));
  await auth.api.signUpEmail({ body: { email, password, name } });
  console.log(`Created user ${email}`);
}

// Only run when invoked directly, not when imported by tests.
if (process.argv[1] && process.argv[1].endsWith("create-user.ts")) {
  main().then(() => process.exit(0)).catch((e) => { console.error(e); process.exit(1); });
}
